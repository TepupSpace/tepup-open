# Accessibility guide

TepUp targets **WCAG 2.2 AA** on every page people use: the learner pages (courses, stories, library, lessons and chapters), the contributor and admin areas, and sign-in. The `/courses` hub and the landing page follow the same rules but keep their own fixed look (no dark mode). This guide explains the rules the code follows, what the automated checks catch, and what a person still has to check by hand. The last audits are [part 1](accessibility-audit-2026-10-07.md) (code) and [part 2](accessibility-audit-2026-10-07-part2.md) (browser run, other areas).

## How it is kept up

| Safeguard | What it does | Where |
|---|---|---|
| Accessibility lint | All `jsx-a11y` strict rules, plus TepUp checks for contrast, tiny text, hard-coded colours and missing focus styles, on learner, contributor, admin and sign-in files | `tepup/eslint.a11y.mjs` |
| Gate | `npm run lint:a11y` must pass. CI runs it on every branch and pull request, and **production deploys wait for it** | `.github/workflows/accessibility.yml`, `deploy-production.yml` |
| Editor warnings | Authors see a warning for an image without alt text and a video without captions or transcript | lesson editors |
| Rules for AI assistants | The "Accessibility" section of `CLAUDE.md` | `CLAUDE.md` |
| Manual checklist | Below, for any change to learner UI | this file |
| Browser kit | axe in real Chromium/WebKit, reflow, keyboard and touch checks against the local Docker stack: `bash a11y-e2e/run.sh` | `a11y-e2e/` |
| Re-audit | Repeat the audit after large UI changes or every six months | `docs/accessibility-audit-*.md` |

The lint only sees one class string at a time and can't run the page. It catches the common slips, not everything. The manual checklist covers the rest.

A real exception gets a comment on that line with the reason, for example `// eslint-disable-next-line jsx-a11y/media-has-caption -- authors haven't added captions to this video yet`. Never switch a rule off for a whole file.

## Colour

- **Use Tailwind palette classes only.** Dark mode works by re-pointing Tailwind's colour variables (`app/reader.css`), so `#fff`, `rgb()` and `bg-[#…]` stay light in dark mode.
- **Text needs 4.5:1:**
  - Meaningful text on white must be **gray-500 or darker** (gray-400 is 2.6:1). On tinted panels (`bg-*-50`, `bg-gray-100`), use **gray-600**: gray-500 drops to about 4.4:1 there.
  - Placeholder and disabled text are exempt, but disabled text that carries an instruction is not.
- **White text needs a dark enough fill:**
  - **-600** for blue, indigo, violet, purple, red, pink and rose.
  - **-700** for green, teal, emerald, lime, orange, amber, yellow, cyan and sky.
  - For example, green-500 is 2.2:1 and green-700 passes.
- **Non-text UI needs 3:1:** input borders, focus rings, progress fills and selected-state outlines. Use gray-500 or darker for input borders (gray-400 is 2.6:1) and -600 fills.
- **Never signal by colour alone.** Right and wrong, selected, completed and current also need text, an icon with a text alternative, or an ARIA state.

## Dark mode

- `app/reader.css` is generated by `scripts/gen-reader-css.mjs` from Tailwind's palette. It applies only when the page has an element with the `.reader` class.
- The learner layouts, the player, and the admin and contributor layouts have one. **A new layout or route outside them needs it on its wrapper.**
- The lesson editor (BlockNote) follows the reading theme too.
- Images are dimmed slightly in dark mode.
- In dark mode, text colours that authors set inline in lesson HTML (often black pasted from Docs/Word) follow the theme instead, so they stay readable.
- `black` stays black: it is only used for backdrops.
- **Known gap:** custom (Sandpack) blocks render in a light iframe and don't follow the reading settings.

## Text size and fonts

- Use the Tailwind scale (rem), **text-xs at the smallest**. The reading-size setting (90–150%) scales the root font size, and `px` sizes don't follow it.
- The "Dễ đọc" font is Andika, chosen because it has full Vietnamese.
- Layouts must survive 150% text and 200% browser zoom without horizontal scrolling at 320 px wide.

## Keyboard

- Every control can be reached with Tab and used with Enter or Space, plus arrow keys where the pattern expects them (tabs, radio groups).
- **Focus is always visible.** Don't use `outline-none` without a `focus-visible:ring-2` in a -600/-700 colour.
- **Don't drop focus:**
  - Don't `disabled` a button the user just pressed; use `aria-disabled` instead.
  - Move focus to newly revealed content.
  - Return focus when a panel closes.
- Sticky header and footer: `scroll-padding` in `globals.css` keeps focused elements from hiding under them.
- Drag-and-drop always has a tap or keyboard alternative.

## Screen readers

- **Names:** every control has an accessible name. Icon-only buttons need `aria-label`, and inputs need a linked `<label>`.
- **State:** use `aria-pressed`, `aria-checked`, `aria-selected`, `aria-expanded` and `aria-current`.
- **Results and changes:**
  - Write them into an always-mounted `<p className="sr-only" aria-live="polite">`. In blocks, use `useAnnouncer()` from `components/blocks/useAnnouncer.ts`: it returns `[message, announce]`, re-announces repeated text, and `toPlainText()` strips markdown first.
  - When a pressed button disappears (for example "Kiểm tra" replaced by the result), move focus to what replaced it, and don't also announce text that focus will read.
  - A live region mounted together with its text is often not read.
  - Use `role="alert"` only for errors the user must act on.
- **Dialogs:**
  - Modal dialogs use `focus-trap-react`, with initial focus inside, Escape to close, and focus returned to the opener.
  - A floating non-modal panel must not set `aria-modal`.
- **Structure:**
  - Exactly one `<h1>` per screen, and headings in order without skipping levels.
  - Landmarks: `header`, `main#main-content` (the skip-link target) and `nav` with unique labels.
  - Each page has a specific `<title>` (`generateMetadata`), because Next only announces client navigation when the title changes.
- **Language:** UI text is Vietnamese. English words in the UI need `lang="en"`, or better, a Vietnamese word.

## Motion

- CSS animations follow `prefers-reduced-motion` through `globals.css`.
- JS smooth scrolling does not, so check `matchMedia('(prefers-reduced-motion: reduce)')` and use `behavior: 'auto'` when it matches.

## Hướng dẫn cho người viết bài (tác giả và người duyệt)

- **Ảnh:**
  - Viết mô tả thay thế (alt) nói điều ảnh muốn truyền đạt, không phải tên tệp.
  - Ảnh chỉ để trang trí thì đánh dấu "ảnh trang trí".
  - Biểu đồ và ảnh chụp màn hình có số liệu: đưa số liệu chính vào alt hoặc vào phần chữ bên cạnh.
- **Video và âm thanh:** thêm phụ đề (tệp WebVTT) hoặc bản ghi lời. Không có cả hai thì người khiếm thính không học được phần đó.
- **Tiêu đề trong bài:** dùng theo thứ tự, không nhảy cấp. Đừng dùng chữ in đậm thay cho tiêu đề.
- **Màu chữ:** đừng dùng màu để nói điều gì đó, ví dụ "các ý màu đỏ là sai". Hãy nói bằng chữ.
- **Liên kết:** chữ của liên kết tự nói nó dẫn đi đâu, ví dụ "Luật Thuế TNCN 2007", không phải "bấm vào đây".
- **Bài tập tuỳ chỉnh (Sandpack):** phải dùng được bằng bàn phím. Người học luôn có nút "Bỏ qua bài tập".
- **Khi duyệt:** đừng duyệt bài còn cảnh báo về alt hoặc phụ đề trong trình soạn.

## Manual checklist for UI changes

Before pushing a change to any UI, check the following in the Docker stack or `next dev`:

1. **Keyboard only:** go through the changed flow with Tab, Shift+Tab, Enter, Space, Escape and the arrow keys. Is focus always visible, never lost, and in a sensible order?
2. **Screen reader smoke test:** NVDA on Windows, VoiceOver on macOS or iOS, or TalkBack on Android. Are the controls named, is state announced, and are results read out?
3. **Zoom:** 200% browser zoom, and text size 150% in the "Aa" panel. Does anything get cut off or overlap?
4. **Dark mode:** switch "Aa" → Tối. Does any text, border or icon disappear or glare?
5. **Phone:** on a real device, check touch targets of at least 24 px, the sticky bars, and text selection.
6. **Reduced motion:** turn on the OS setting. Is there still no animated scrolling?
7. **`npm run lint:a11y`** passes.
